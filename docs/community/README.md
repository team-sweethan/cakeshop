# 커뮤니티 기능 안내

> **처음 보는 사람이 쉽게 볼 수 있는 문서 작성함.**<br/> 
> 기능이 어떻게 생겼는지 빠르게 보려고 만든 것이고, 규칙의 정본은 `DOMAIN.md`임.
> <br/>둘이 다르게 적혀 있으면 **`DOMAIN.md`가 옳다.** 이 문서를 근거로 코드를 고치지 않는다.

## 한 줄로

**고객이 케이크에 대해 질문하고 후기를 나누는 게시판**이다. 글을 쓰고, 댓글을 달고, 좋아요를 누르고, 문제가 있는 글은 신고한다. 관리자는 신고를 보고 글을 가릴 수 있다.

## 화면은 6개

| 화면 | 누가 보나 | 무엇을 하나 |
|---|---|---|
| 글 목록 | **누구나** (로그인 안 해도) | 글을 20개씩 본다. 분류(질문·후기·자유)로 거르고, 최신순/조회수순으로 정렬한다. 맨 위에 **인기글 10개**가 함께 뜬다 |
| 글 상세 | **누구나** | 본문과 댓글을 본다. 로그인하면 댓글·좋아요·신고를 할 수 있다 |
| 새 글 쓰기 | 로그인한 회원 | 분류를 고르고 제목·본문을 쓴다 |
| 글 수정 | 글쓴이 본인 | 제목·본문·분류를 고친다. 고치면 화면에 `(수정됨)`이 붙는다 |
| 관리자 목록 | 관리자 | 신고가 많은 순으로 정렬해 조치할 글을 찾는다 |
| 관리자 상세 | 관리자 | 글을 차단하거나, 신고를 기각한다 |

## 팀원이 알아두면 좋은 규칙

**1. "삭제"와 "차단"은 다른 일이다**

- **삭제** = 글쓴이가 자기 글을 없애는 것. **되돌릴 수 없다** (휴지통 없음)
- **차단** = 관리자가 문제 있는 글을 가리는 것. 나중에 해제할 수 있다

차단된 글은 **글쓴이만** 볼 수 있고, 차단 사유가 함께 보인다. 왜 사라졌는지 모르면 고칠 수도 없기 때문이다. 대신 **글쓴이도 차단된 글은 수정·삭제할 수 없다** — 신고 처리의 증거라서 없앨 수 없어야 한다.

**2. 관리자가 할 수 있는 일은 생각보다 적다**

차단 / 차단 해제 / 신고 기각, **이 셋뿐이다.** 관리자는 남의 글도 댓글도 지울 수 없다. 글을 지우는 건 글쓴이만, 댓글을 지우는 건 그 댓글을 쓴 사람만 할 수 있다. 그래서 관리자 화면에 삭제 버튼이 없는 게 **빠뜨린 게 아니라 의도한 것**이다.

**3. 조회수는 같은 사람이 계속 새로고침해도 안 오른다**

같은 사람이 같은 글을 **10분 안에** 여러 번 열면 1번만 센다. 조회수로 글 순위를 정하기 때문에, 새로고침만으로 순위가 오르면 안 된다. (다만 작정하고 조작하는 건 못 막는다. 막는 건 사람의 반복 조회까지다.)

**4. 인기글은 실시간이 아니라 하루에 한 번 정해진다**

매일 새벽에 프로그램이 **최근 7일간의 활동**을 한 번 계산해서 그날의 순위를 확정한다. 점수는 이렇게 매긴다.

| 신호 | 점수 | 왜 |
|---|---|---|
| 좋아요 1개 | **25점** | 회원당 1번만 누를 수 있어 제일 믿을 만하다 |
| 댓글 쓴 사람 1명 | **15점** | 한 사람이 댓글을 10개 달아도 15점이다. **댓글 개수가 아니라 사람 수를 센다** |
| 조회수 1 | **1점** | 제일 조작하기 쉬워서 제일 낮게 준다 |

한 번 정해진 순위는 **나중에 좋아요를 취소해도 바뀌지 않는다.** 그날의 기록이기 때문이다.

화면에서는 이렇게 보인다.

- 목록 **1쪽**에서, 분류를 안 골랐을 때만 뜬다. 분류를 고르면 사라지는 게 정상이다 — 안 그러면 필터가 안 먹은 것처럼 보인다
- **언제 정한 순위인지 날짜가 함께 뜬다** (`2026.03.01 기준`). 새벽 계산을 한 번 건너뛰면 자동으로 어제 것이 나오는데, 날짜가 없으면 낡은 순위를 오늘 것으로 착각한다
- 인기글 줄에는 **조회수·좋아요·댓글 숫자가 없다.** 같은 글이 아래 목록에도 나오고 그쪽은 지금 숫자라, 한 화면에 숫자가 둘이면 어느 쪽도 못 믿게 된다
- 보여줄 게 없으면 **자리가 통째로 사라진다.** 제목만 덩그러니 남기지 않는다

**5. 댓글은 단순하게 간다**

대댓글 없음, 댓글 수정 없음. 지운 댓글은 목록에서 사라지지 않고 `삭제된 댓글입니다` 자리로 남는다. 댓글이 20개를 넘으면 `이전 댓글 더 보기`로 늘려 본다.

**6. 신고는 취소할 수 없다**

이미 신고한 글을 또 신고하면 에러가 난다("이미 신고한 게시글입니다"). 조용히 성공했다고 하면 접수된 줄 알지만 실제로는 아무 일도 안 일어나기 때문이다. 자기 글은 신고할 수 없다.

**7. 회원이 탈퇴해도 글은 남는다**

글쓴이 이름만 `탈퇴한 회원`으로 바뀐다. 질문글이 사라지면 거기 달린 답변들이 맥락을 잃기 때문이다.

## 글자 수 제한

| 항목 | 제한 |
|---|---|
| 제목 | 1~100자 |
| 본문 | 1~5000자 |
| 댓글 | 1~500자 |
| 신고 사유 / 차단 사유 | 1~500자 |

공백만 입력하면 거부된다. 본문에 HTML을 넣어도 태그가 그대로 글자로 보인다(보안 때문에 일부러 그렇게 한다).

## 지금 어디까지 됐나

**목록·상세·글쓰기·댓글·좋아요·신고·관리자 차단·조회수·정렬·인기글**까지 다 된다. 인기글은 목록 화면 맨 위에 뜨는데, **아직 배치가 한 번도 안 돈 환경에서는 그 자리가 통째로 비어 있는 것이 정상이다** — 고장이 아니다.

자세한 진행 상황은 `PLAN.md`의 `조각 순서` 표를 본다.

## 더 알고 싶으면

| 궁금한 것 | 볼 문서 |
|---|---|
| "이 기능의 규칙이 정확히 뭐지?" | **`DOMAIN.md`** — 규칙의 정본 |
| "지금 뭘 하고 있고 다음은 뭐지?" | **`PLAN.md`** — 작업 순서와 진행 상황 |
| "이 화면에 무엇이 언제 보이지?" | **`DOMAIN.md`** 4.3과 그 화면의 `specs/*.md`. 실제 출력은 템플릿과 `CommunityScreenRenderingTests` |
| "이 기능 하나의 명세만 보고 싶다" | **`specs/`** — 어느 파일인지는 `DOMAIN.md` 0.1의 기능 목록이 가리킨다 |

`DOMAIN.md`와 `PLAN.md`는 개발자용이라 길고 어렵다. **"왜 이렇게 만들었나"가 대부분인데, 그 이유를 지우면 다음 사람이 반대로 만들어도 아무도 모르기 때문에** 일부러 길게 적어 둔 것이다.
