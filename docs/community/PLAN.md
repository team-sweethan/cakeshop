# Community 진행 계획

> **이 문서는 진행 상태와 번호 인덱스만 갖는다.** 규칙도 결정 근거도 여기 없다 — 아래 파이프라인의
> 각 자리가 소유하고, 여기에는 그 자리로 가는 **번호와 한 줄**만 남는다.
>
> 2026-08-20에 결정 로그와 위험 본문을 각 자리로 옮겼다. 옮기기 전 이 파일은 173KB였고 그중
> 결정 로그 한 표가 113KB였다. **다시 부풀면 같은 자리를 다시 잘라야 한다** — 본문은 여기 쌓지 않는다.

## 문서 파이프라인

문제가 발견되어 규칙이 되고 코드가 되기까지, 단계마다 소유하는 자리가 다르다.

| 단계 | 자리 | 무엇이 있나 |
|---|---|---|
| **문제 발견** | `reviews/` | `reviews/risks.md` — 아직 닫히지 않았거나 알고 감수한 위험(R#)<br>`reviews/findings.md` — PR 리뷰·자체 점검의 지적과 그 처리 |
| **해결 방향** | `decisions/` | `ADR-00N-*.md` — 한 줄로 재구성이 안 되는 결정<br>`decisions/decision-log-1st.md`·`decisions/decision-log-2nd.md` — 날짜순 결정 기록 |
| **현재 규칙** | `specs/` · `DOMAIN.md` | **정본.** 지금 지켜야 하는 것. 어느 spec인지는 `DOMAIN.md` 0.1절 기능 목록이 가리킨다 |
| **구현** | 코드 · 테스트 | 규칙을 실제로 지키는 자리. 무엇이 무엇을 고정하는지는 아래 하네스 인덱스 |
| **완료 이력** | `history/` · Git | 끝난 조각의 기록. 지금 구속하지 않는다 |

**규칙이 바뀌면 고칠 곳은 그 기능의 `specs/*.md`다.** 이 문서에서는 조각 상태 한 줄만 바뀐다.
여러 기능에 걸리는 것만 `DOMAIN.md`이고, `DOMAIN.md` 6절은 옛 절 번호를 지금 자리로 보내는 매핑
표일 뿐이라 거기에 규칙을 적지 않는다. 갱신 대상의 전체 목록은 `domain/community/CLAUDE.md`의
조각 완료 시 문서 동기화 절에 있다.

**`reviews/`·`decisions/`·`history/`는 기본으로 읽지 않는다.** 셋 다 지금 하는 일을 구속하지 않는다 —
필요할 때 해당 파일 **하나**만 연다.

## 작업 방식

한 번에 **수직 조각 하나**만 한다. 조각 하나는 DB → Mapper → Service → Controller → 화면 → 테스트까지 닿아야 하고, 끝나면 브라우저에서 동작하고 `gradlew test`가 통과하고 CI가 초록불이어야 한다.

조각마다 AI에게 주는 지시는 이 형태를 따른다:

```
docs/community/DOMAIN.md 0.1절에서 <이 조각의 기능 ID>가 어느 spec인지 찾고,
그 spec과 DOMAIN.md의 관련 공통 절, 기존 코드를 먼저 읽고 구현 계획을 보고해.
<조각 내용>을 구현해.
구현 후 ./gradlew clean test를 실행하고, <이 조각의 검증 항목>을 확인해.
끝나면 변경 파일, 실행한 검증, 남은 위험을 보고해.
문서는 파이프라인 자리에 맞춰 갱신해 — 규칙이 바뀌었으면 그 spec,
방향을 골랐으면 decisions/decision-log-2nd.md, 문제가 나왔으면 reviews/,
조각 상태 한 줄만 PLAN.md.
```

**AI가 실수하면 그 자리에서 고치고 끝내지 않고 하네스로 승격시킨다.** 같은 실수가 두 번 일어날 수 없게 테스트·제약·규칙 문서 중 하나로 고정한다.

## 번호 인덱스

**아래 세 표는 번호와 소유처만 갖는다.** 근거는 그 번호를 소유하는 문서 본문에 있고 여기 두 벌로 적지 않는다.

> **`D#`은 이 저장소에서 두 가지를 뜻한다. 섞어 읽지 않는다.**
> 조각 순서 표와 spec 에 나오는 `D1`·`D2`·`D3`·`D4`는 `DOMAIN.md` 0.1절의 **기능 ID**(작성자 표시명·메인
> 인기글 계약·메인 공지 계약·댓글 알림)이고, 아래 번호 인덱스의 `D1`~`D11`은 **조각 7 결정**(점수식·cron·
> 멱등성 등)이다. 공유 seed 와 migration 이 `PLAN.md D3`로 가리키는 것은 **후자**다.

**그런데 번호는 여기 남아야 한다.** `PLAN.md D3`·`PLAN.md R35`·`PLAN.md 조각 7b`처럼 **번호로**
이 문서를 가리키는 파일이 실제로 있고, 그중 공유 migration은 고칠 수 없다. 번호로 들어온 사람이
여기서 **한 홉 안에** 근거에 닿을 수 있어야 한다.

번호로 이 문서를 가리키는 곳: `V20260804_102934__switch_post_view_window_to_10_minutes.sql`·
`V20260804_130038__add_post_view_count_sort_index.sql`·`V20260805_073107__add_daily_popular_posts.sql`·
`V20260812_065639__add_community_notices.sql`·`V20260818_234248__add_post_like_count_sort_index.sql`·
`seed-community.sql`·`ClockConfig`·`PopularPostScheduler`·`PopularPostBatchService`·`PostSort`·
`MariaDbTestContainerConfig`, 그리고 `specs/`의 여러 절.
