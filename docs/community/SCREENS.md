# Community 화면 명세

> 도메인 규칙의 정본은 `docs/community/DOMAIN.md`, 진행 순서는 `docs/community/PLAN.md`다.
> 이 문서는 **화면에 무엇이 어떤 조건에서 보이는지**만 다룬다.

화면별 명세는 `docs/community/screens/` 아래에 **화면 하나에 파일 하나**로 둔다. 이 문서는 그 파일들의 인덱스이자 형식 규약이다.

| 화면 | 주소 | 상태 | 조각 | 파일 |
|---|---|---|---|---|
| 목록 | `GET /community` | 구현됨 | 1 | [screens/list.md](screens/list.md) |
| 상세 | `GET /community/{postId}` | 구현됨 | 1 | [screens/detail.md](screens/detail.md) |
| 글쓰기 | `GET /community/new` | 구현됨 | 2 | [screens/new.md](screens/new.md) |
| 수정 | `GET /community/{postId}/edit` | 구현됨 | 2 | [screens/edit.md](screens/edit.md) |
| 관리자 목록 | `GET /admin/community` | 구현됨 | 5 | [screens/admin-list.md](screens/admin-list.md) |
| 관리자 상세 | `GET /admin/community/{postId}` | 구현됨 | 5 | [screens/admin-detail.md](screens/admin-detail.md) |

**인기글과 조회수 정렬 옵션은 이 표에 줄이 없고, 앞으로도 생기지 않는다.** 둘 다 새 화면이 아니라 **목록 화면이 넓어진 것**이라 `screens/list.md`가 받는다(조각 7a·7c에서 결정, DOMAIN.md 6.9와 9절). 인기글을 별도 화면으로 빼는 안은 닫았다 — 인기글만 보러 들어오는 사람은 없고, 목록에 가는 길에 눈에 띄어야 의미가 있다.

**정본은 각 파일의 `- 상태:` 줄이다.** 화면 상태가 바뀌면 파일을 먼저 고치고 이 표를 맞춘다. 이 표는 같은 사실을 두 번 적어 둔 인덱스라 한쪽만 고치면 조용히 갈라진다 — 화면을 바꾸는 PR에서 함께 확인한다.

**화면이 아닌 것.** 삭제·좋아요·신고·댓글은 새 페이지가 아니라 **상세 화면에 붙는 버튼과 구역**이다. `screens/detail.md`의 "상세에 앞으로 붙는 것"에 정리했다.

## 이 문서를 믿을 수 있는 범위

한때 `CommunityScreenDocTests`가 이 문서들을 파싱해 템플릿·테스트와 대조했지만 2026-08-09에 걷어냈다
(`docs/testing.md` 4절이 문서·소스를 파싱하는 테스트를 삭제 대상으로 정한다). **지금 문서와 화면의
일치를 지키는 것은 사람이다** — 화면을 바꾸는 PR에서 해당 명세를 함께 고친다.

없는 안전망을 있다고 적지 않기 위해 그 한계를 분명히 해 둔다.

- 문구를 바꾸고 문서를 안 고쳐도 빌드는 깨지지 않는다.
- 템플릿에 새 블록을 넣고 문서에 안 적어도 아무도 모른다. 조건부로만 보이는 블록(차단 안내, 빈 목록,
  페이지네이션)은 평소 화면에 없어 리뷰에서도 눈에 띄지 않으므로 특히 주의한다.
- `계획` 화면을 만들고 상태를 안 바꿔도 드러나지 않는다.

**화면에 실제로 무엇이 나오는지는 `CommunityScreenRenderingTests`가 지킨다.** 이 문서는 그 결과를
사람이 읽을 수 있게 정리한 명세이고, 두 곳이 갈라지면 렌더링 테스트와 실제 화면이 정본이다.

## 화면 파일 형식

화면을 추가하려면 `screens/`에 파일을 하나 만들고 위 인덱스 표에 줄을 더한다. 파일 하나에 화면 하나다.

```markdown
# 화면 이름 — `GET /주소`

- 상태: 구현됨 (조각 1)
- 템플릿: `customer/community/list.html`
- 핸들러: `CommunityController.list`
- 접근: 공개

## 화면 문자열

| 문자열 | 언제 보이나 | 고정한 테스트 |
|---|---|---|
| `커뮤니티` | 항상 (제목) | `CommunityScreenRenderingTests.communityList_rendersPostRow` |
```

- 제목은 `# 화면 이름 — `GET /주소`` 꼴이고, 주소는 인덱스 표의 `주소` 칸과 같아야 한다.
- 상태 뒤에는 `(조각 1)`처럼 근거를 붙여도 된다.
- 문자열과 테스트 이름은 백틱으로 감싼다.
- 고정한 테스트가 없으면 `없음`으로 적는다. 없는 것을 있다고 적는 것보다 낫다.
- `계획` 화면에는 문자열 표를 두지 않는다. 대조할 템플릿이 아직 없다.

### 상태 표기

| 표기 | 뜻 |
|---|---|
| `구현됨` | DB까지 연결되어 실제로 동작한다 |
| `목업` | 템플릿은 있지만 하드코딩이다. 화면이 **거짓말을 하고 있다** |
| `계획` | 템플릿이 아직 없다. 만들면서 이 표기를 지운다 |

## 만들지 않는 화면

`DOMAIN.md` 2절이 범위 밖으로 정한 것들이다. 요청이 들어오면 여기를 먼저 본다.

| 화면 | 왜 안 만드나 |
|---|---|
| 검색 | 범위 밖. 제목·본문 LIKE 검색은 인덱스를 못 타서 글이 늘면 목록 전체가 느려진다 |
| 무한 스크롤 | 범위 밖 (2차). 게시글 목록은 쪽 번호 페이징으로 간다. **댓글의 `이전 댓글 더 보기`는 이것이 아니다** — 스크롤이 아니라 사용자가 누를 때만 늘어나고, 주소가 바뀌는 링크라 JS 없이 동작한다 (DOMAIN.md 6.4) |
| 이미지 첨부 | 범위 밖. `post_images` 테이블은 있지만 쓰지 않는다 |
| 카테고리 관리 화면 | 범위 밖. 카테고리는 migration으로 주입한다 (DOMAIN.md 6.8) |
| 대댓글 | 2차. `parent_comment_id`를 코드에 등장시키지 않는다 (6.4) |
