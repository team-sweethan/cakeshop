# Cart 도메인 정본

> 이 문서는 Cart 도메인의 **확정된 업무 규칙**을 기록한다.
> 프로젝트 전체 규칙은 [`AGENTS.md`](../../AGENTS.md)가 상위 정본이며, 충돌하면 `AGENTS.md`가 우선한다.
> 테이블 구조는 [`schema/cart.md`](../schema/cart.md), 여러 도메인의 합의가 아직 필요한 질문은
> [`team-plan.md`](../team-plan.md)를 본다.

## 한 문장 정의

Cart 도메인은 로그인한 고객이 주문 전에 일반 상품과 선택 옵션, 수량 및 요청사항을 임시로 보관하는
장바구니를 소유한다.

## 1. 기능 범위

| 기능 | 경로 |
|---|---|
| 내 장바구니 조회 | `GET /cart` |
| 로그인 후 상품으로 돌아가기 | `GET /cart/continue/{productId}` |
| 항목 추가 | `POST /cart/items` |
| 수량 변경 | `POST /cart/items/{itemId}/quantity` |
| 비동기 수량 변경 | `POST /cart/items/{itemId}/quantity/async` |
| 장바구니 항목 수 조회 | `GET /cart/count` |
| 단건 삭제 | `POST /cart/items/{itemId}/delete` |
| 선택 삭제 | `POST /cart/items/delete-selected` |
| 전체 삭제 | `POST /cart/items/delete-all` |

- 장바구니 기능은 인증된 `USER`만 사용한다.
- 회원마다 하나의 장바구니를 가지며 처음 항목을 담을 때 없으면 생성한다.
- 현재 장바구니에는 `GENERAL` 상품만 담는다.
- `CUSTOM` 주문 제작 상품은 장바구니에 담지 않고 주문 제작 흐름에서 옵션과 요청 내용을 입력한다.

## 2. 소유권과 변경 단위

- 모든 조회·수정·삭제는 인증된 `MemberDetails.memberId`를 기준으로 본인 장바구니에만 적용한다.
- 요청에서 전달된 장바구니 ID나 회원 ID를 소유권 판단에 사용하지 않는다.
- 다른 회원의 항목과 존재하지 않는 항목은 모두 `ITEM_NOT_FOUND`로 처리한다.
- 선택 삭제는 중복 ID를 제거한 뒤 요청한 모든 항목이 본인 소유일 때만 성공한다.
- 옵션, 이미지와 항목 삭제는 하나의 트랜잭션으로 처리한다.
- 전체 삭제는 장바구니가 존재하지 않아도 성공으로 처리한다.

## 3. 상품과 수량

- 항목 추가와 수량 변경 시 상품 도메인의 공개 Service로 현재 판매 여부, 상품 유형과 재고를 다시 확인한다.
- 수량은 1 이상이어야 한다.
- 같은 상품이 옵션이나 요청사항에 따라 여러 행으로 나뉘어도 현재 유효한 행의 상품별 총수량으로 재고를 검증한다.
- 재고 수량이 있는 상품은 상품별 총수량이 현재 재고를 초과할 수 없다.
- 재고 수량이 `NULL`인 상품도 한 상품당 최대 10개까지만 담을 수 있다.
- 판매 중지, 재고 부족, 주문 제작 상품 또는 현재 옵션 구성과 일치하지 않는 항목은 이용 불가로 표시한다.
- 이용 불가 항목은 장바구니에서 자동 삭제하지 않고 상품 금액, 옵션 금액과 전체 합계 계산에서 제외한다.
- 헤더 등에 표시하는 장바구니 개수는 수량 합계가 아니라 장바구니 항목 행의 개수다.

## 4. 옵션과 항목 병합

- 필수 옵션 그룹은 하나 이상의 옵션을 선택해야 한다.
- 단일 선택 그룹에서는 두 개 이상의 옵션을 선택할 수 없다.
- 중복 옵션 ID나 해당 상품의 현재 옵션 그룹에 없는 옵션 ID는 허용하지 않는다.
- 장바구니에는 선택 당시 옵션 ID, 옵션명과 추가 금액 스냅샷을 저장한다.
- 현재 옵션의 이름, 가격 또는 활성 상태가 스냅샷과 달라지면 해당 장바구니 항목을 이용 불가로 처리한다.
- 같은 상품, 같은 옵션 스냅샷, 같은 요청사항인 항목을 다시 담으면 새 행 대신 기존 수량에 합산한다.
- 옵션 ID가 같아도 저장된 옵션명이나 추가 금액이 다르면 기존 항목과 합치지 않는다.
- 요청사항은 정규화 전 입력값을 기준으로 최대 2,000자로 제한한다.
- 길이 검증을 통과한 요청사항은 앞뒤 공백을 제거하고 빈 값은 `NULL`로 저장한다.

## 5. 화면 금액

- 상품 기본 금액은 조회 시점의 현재 상품 가격을 사용한다.
- 옵션 금액은 현재 옵션 구성과 일치한다고 검증된 장바구니 옵션 스냅샷을 사용한다.
- 항목 금액은 `(기본 금액 + 옵션 금액) × 수량`으로 계산한다.
- 장바구니의 기본 금액 합계, 옵션 금액 합계와 전체 합계에는 이용 가능한 항목만 포함한다.
- 장바구니 화면의 금액은 주문 확정 금액이 아니며 주문 생성 단계에서 다시 검증한다.

## 6. 확정된 도메인 연계 결정사항

### 주문 생성

- 주문 도메인은 `CartOrderQueryService`로 인증 회원이 선택한 장바구니 항목을 조회한다.
- 공개 응답은 장바구니 항목 ID, 상품 ID, 수량, 요청사항과 선택 옵션 ID만 제공한다.
- 요청한 항목이 비어 있거나 일부라도 본인 소유가 아니면 주문 도메인에 결과를 제공하지 않는다.
- 상품 상태, 옵션과 최종 금액은 주문 도메인이 주문서 표시와 주문 저장 시점에 다시 검증한다.

### 결제 완료 후 정리

- 일반 주문의 결제·주문·쿠폰·재고 처리가 커밋된 뒤 발행되는 이벤트로 장바구니 정리를 시작한다.
- 주문에 연결된 회원과 장바구니 항목만 삭제한다.
- 주문 생성 시점의 수량과 현재 장바구니 수량이 같을 때만 해당 항목을 삭제한다.
- 사용자가 먼저 삭제했거나 이미 정리된 항목은 성공으로 처리해 재실행할 수 있게 한다.
- 결제가 이미 커밋된 뒤의 장바구니 정리 실패는 고객의 결제 결과를 되돌리지 않는다.

## 7. 현재 범위 밖

- 비회원 장바구니와 로그인 후 비회원 장바구니 병합
- 주문 제작 상품의 장바구니 저장
- 장바구니 항목 이미지 등록

`cart_item_images` 테이블이 존재하더라도 현재 등록 흐름이 없으므로 구현된 기능으로 간주하지 않는다.
위 기능을 시작할 때는 관련 상품·주문 담당자와 범위 및 소유 계약을 먼저 결정한다.
