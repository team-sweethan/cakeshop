# 조각 5 — 관리자 숨김 (#112, PR #189 머지 완료)

> **끝난 조각의 기록이다. 지금 구속하지 않는다.**
> 이 조각이 만든 규칙의 정본은 `../specs/review-admin.md`.
> 조각 순서와 진행 상태는 `../PLAN.md`, 발견된 문제는 `../reviews/`,
> 방향을 고른 판단은 `../decisions/`에 있다.

**검색 계약(`writer`·`product`)을 새로 만들었다.** 둘 다 조각 1·3에서 내가 만든 파일에 메서드를 더한 것이라 **수민·주환님 파일은 그대로다.** 시그니처는 `../DOMAIN.md` 2.7 표에 있고, PR 리뷰어로 두 분을 지정해 확인받는다. `members`·`order_items`를 JOIN하지 않는다. 후기를 먼저 페이지한 뒤 이름으로 거르면 **화면의 건수와 실제 건수가 갈린다.**

**관리자 화면이지만 ReadModel이 아니다.** 12절의 ReadModel 예외는 집계·요약하는 통계·대시보드에만 열린다.

- 관리자 목록(`GET /admin/reviews`)과 검색·필터, 관리자 상세 화면(C3)
- **숨김과 해제를 함께 만들었다** — `POST .../block`(`PUBLISHED → BLOCKED`), `POST .../unblock`(`BLOCKED → PUBLISHED`). **집계 재호출도 양쪽 다.**
  - 해제를 빼면 잘못 숨긴 후기를 되돌릴 방법이 없다. C1이 모든 상태를 보여 주는 이유가 바로 해제 대상을 찾기 위해서다
- 목업의 `삭제` 버튼은 걷어냈다 — 관리자 조치는 숨김뿐이다(`docs/community/DOMAIN.md` 6.7 선례)
- 목업에 없던 **상태 필터를 더했다.** 숨긴 후기만 모아 보는 것이 이 화면의 실제 쓰임이다
- 재집계 진입점 `ReviewService.recalculateRating`을 공개하고 `Propagation.MANDATORY`를 걸었다. "후기 쓰기와 같은 트랜잭션"이라는 요구가 주석이 아니라 **호출 시점에 검사되는 조건**이 된다

**검증**: 비관리자의 숨김·해제 접근 거부(화면 숨김이 아니라 Security)와 CSRF, 숨김 후 집계에서 빠지는지, **해제 후 집계에 돌아오는지**, 금지된 전이(`DELETED → BLOCKED`) 거부, **검색어에 아무도 안 걸렸을 때 전체 목록이 나오지 않는지**, **`%` 한 글자가 전체를 조회하지 않는지**, 모르는 `rating` 값이 전체로 떨어지는지, **A5 삭제와 C4 숨김의 동시 실행**(둘 중 하나만 적용되고 집계가 실제 행과 맞는지, 그리고 상품 잠금을 기다리는 동안 커밋된 삭제를 원인 재판정이 보는지).
