# Review 도메인 전체 흐름

> 이 문서는 Review 도메인의 **전체 흐름**만 다룬다. 흐름 위 각 지점의 규칙·결정·근거는 `docs/review/SPEC.md`가 정본이다.
> 작업 순서·진행 상태·위험·결정 로그는 `docs/review/PLAN.md`를 본다.
> 프로젝트 전체 규칙은 `AGENTS.md`가 상위 정본이다.
>
> **여기에 결정을 적지 않는다.** 같은 결정을 두 곳에 적으면 한쪽이 낡고, 다음 작업자가 어느 쪽을 믿어야 할지 알 수 없게 된다.

## 1. 한 문장 정의

Cakeshop 후기는 **케이크를 실제로 받아 간 고객이 그 주문 상품에 대해 남기는 평가**다.

커뮤니티의 `REVIEW`(후기) 카테고리와 다르다. 커뮤니티 후기는 누구나 쓰는 글이고, 이쪽은 **주문 이력이 있어야만 쓸 수 있는 평점 데이터**다.

## 2. 전체 흐름

```
[주문]                    [후기]                      [상품]
  │                         │                           │
  ├─ 결제 완료               │                           │
  ├─ 픽업 완료 ──────────────┤                           │
  │  (PICKED_UP)      작성 자격 발생                     │
  │                         │                           │
  │                    후기 작성 ────────────────────► 평점 집계
  │                    (주문상품당 1개)            average_rating
  │                         │                      review_count
  │                         │                           │
  │                         ▼                           ▼
  │                    상품 상세에 노출 ◄─────────────────┘
  │                         │
  │                         ▼
  │                   [관리자] 목록 확인
  │                         │
  │                    ├─ 답글 (후기당 1개) ──► [알림] 작성자에게
  │                    └─ 숨김 (status)
```

**입구는 하나다.** 후기는 스스로 시작되지 않는다. 주문이 `PICKED_UP`에 도달하는 것이 유일한 입구이고, `OrderStatus.PICKED_UP`은 종착 상태(나가는 전이 없음)라 **자격은 한 번 생기면 사라지지 않는다.**

**자격의 단위는 주문이 아니라 주문 상품(`order_items`)이다.** 케이크 세 종류를 한 번에 샀으면 후기도 세 개다.

**집계로 나가는 흐름이 지금 끊겨 있다.** `products.average_rating`·`review_count`는 `ProductMapper.xml`이 조회할 뿐 아니라 **정렬 기준으로 쓰는데**(`review_count DESC, average_rating DESC`) 값을 쓰는 애플리케이션 코드가 없다. 운영에서는 영구히 0이다. 후기 작성·수정·삭제·숨김·숨김 해제가 모두 이 갱신을 불러야 흐름이 닫힌다.

## 3. 흐름이 닿는 도메인

리뷰는 이 넷과 이어지고, **연결은 전부 그 도메인의 공개 계약을 거친다**(`SPEC.md` 2.7 — 다른 도메인 테이블을 JOIN하지 않는다).

| 도메인 | 방향 | 무엇 | 상태 |
|---|---|---|---|
| 주문 | 주문 → 후기 | `PICKED_UP` 도달이 작성 자격. 대상은 `order_items` | 계약 미합의 (조각 1) |
| 상품 | 후기 → 상품 | 평점 집계(`average_rating`, `review_count`) | **흐름 끊김.** 계약 시그니처 미합의 (조각 2 / #33) |
| 회원 | 회원 → 후기 | 작성자·관리자 식별. 탈퇴해도 행은 남는다 | 계약 미합의 (조각 3) |
| 알림 | 후기 → 알림 | 등록 시 관리자에게, 답글 시 작성자에게 | 규격이 PR #107(미머지)에 있음 (조각 7) |

## 4. 어디를 보면 되는지

| 찾는 것 | 문서 |
|---|---|
| 기능 단위 명세, 상태 모델, 평점, 권한, 오류 코드, 화면 | `SPEC.md` 1~8절 |
| 아직 안 정해진 것 | `SPEC.md` 9절 |
| 조각 순서, 조각별 선행 합의와 검증 항목 | `PLAN.md` |
| 위험, 결정 로그 | `PLAN.md` |
| 도메인 작업 규칙 (구현 시작 전) | `src/main/java/com/cakeshop/domain/review/CLAUDE.md` |
