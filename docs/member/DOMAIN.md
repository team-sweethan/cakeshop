# Member 도메인 정본

> 이 문서는 Member 도메인의 **확정된 업무 규칙**을 기록한다.
> 프로젝트 전체 규칙은 [`AGENTS.md`](../../AGENTS.md)가 상위 정본이며, 충돌하면 `AGENTS.md`가 우선한다.
> 테이블 구조는 [`schema/member.md`](../schema/member.md), 여러 도메인의 합의가 아직 필요한 질문은
> [`team-plan.md`](../team-plan.md)를 본다.

## 한 문장 정의

Member 도메인은 고객과 관리자의 식별 정보, 인증 수단, 프로필과 계정 상태를 소유한다.

## 1. 기능 범위

| 구분 | 기능 | 경로 |
|---|---|---|
| 비회원 | 일반 회원가입 | `GET /signup`, `POST /join` |
| 비회원 | 회원가입 이메일 인증 | `POST /email-verifications/signup/**` |
| 비회원 | 고객·관리자 로그인 | `GET /login`, `GET /admin/login` |
| 비회원 | 이메일 찾기 | `GET·POST /find-email` |
| 비회원 | 비밀번호 재설정 | `GET /find-password`, `GET·POST /reset-password` |
| 비회원 | 소셜 로그인·추가정보 회원가입 | OAuth 로그인, `GET·POST /oauth/signup` |
| 고객 | 마이페이지·프로필 조회 | `GET /mypage`, `GET /mypage/profile` |
| 고객 | 프로필·비밀번호 수정 | `POST /mypage/profile/update` |
| 고객 | 회원 탈퇴 | `POST /mypage/withdraw` |
| 관리자 | 회원 목록·검색·상세 | `GET /admin/members`, `GET /admin/members/{memberId}` |
| 관리자 | 회원 정지·정지 해제 | `POST /admin/members/{memberId}/suspend`, `POST /admin/members/{memberId}/activate` |

회원 도메인은 다른 도메인의 주문, 결제, 쿠폰, 게시글, 후기, 알림과 채팅 데이터를 소유하지 않는다.
해당 데이터가 필요한 화면은 데이터 소유 도메인의 공개 Service 계약을 사용한다.

## 2. 역할과 인증

- 역할은 고객 `USER`와 관리자 `ADMIN`으로 구분한다.
- 고객 포털은 `USER`, 관리자 포털과 `/admin/**`는 `ADMIN`만 접근한다.
- DB의 현재 상태가 `ACTIVE`인 계정만 일반 로그인과 소셜 로그인을 허용한다.
- 회원가입·이메일 인증 입력은 앞뒤 공백을 제거하고 소문자로 바꾼 뒤 형식과 길이를 검증한다.
- 소셜 로그인 이메일도 앞뒤 공백을 제거하고 소문자로 정규화한다.
- 폼 로그인 입력은 앞뒤 공백을 제거해 조회하고, 인증 정보에는 DB에 저장된 이메일을 사용한다.
- 비밀번호 원문은 저장하지 않고 `PasswordEncoder`로 만든 해시만 저장한다.
- 로그아웃은 POST와 CSRF 검증을 사용하고 세션, 인증 정보와 `JSESSIONID`를 제거한다.

## 3. 회원 상태

| 현재 상태 | 허용 전이 | 의미 |
|---|---|---|
| `ACTIVE` | `SUSPENDED`, `WITHDRAWN` | 정상 이용 회원 |
| `SUSPENDED` | `ACTIVE`, `WITHDRAWN` | 관리자에 의해 이용이 정지된 회원 |
| `WITHDRAWN` | 없음 | 복구하지 않는 탈퇴 종착 상태 |

- 상태 전이는 Service에서 현재 상태를 다시 확인하고 조건부 UPDATE 결과가 1건일 때만 성공한다.
- 관리자 정지와 정지 해제는 `USER` 계정에만 적용하며 `ADMIN` 계정에는 적용하지 않는다.
- 정지와 정지 해제 사유는 앞뒤 공백을 제거한 뒤 빈 값을 허용하지 않고 최대 500자로 제한한다.
- 관리자 상태 변경과 `member_status_histories` 이력 저장은 하나의 트랜잭션으로 처리한다.
- 정지 이력에는 대상 회원, 처리 전후 상태, 사유, 인증된 처리 관리자와 처리 시각을 남긴다.
- 회원을 정지하면 해당 이메일로 등록된 기존 로그인 세션을 만료시킨다.
- 정지·탈퇴가 진행 중인 주문·결제·쿠폰·채팅에 미치는 영향과 정지 회원의 세부 조회·쓰기 범위는
  [`team-plan.md`](../team-plan.md)의 미결정 항목을 따른다.

## 4. 일반 회원가입과 이메일 인증

- 신규 회원의 이메일은 중복될 수 없으며 가입 전에 이메일 소유 인증을 완료해야 한다.
- 인증번호는 숫자 6자리이며 원문 대신 BCrypt 해시를 저장한다.
- 인증번호는 발송 후 5분 동안만 확인할 수 있고, 인증 완료 권한은 최초 확인 후 10분 동안 유효하다.
- 5분이 지난 인증번호로 다른 세션에 인증 완료 권한을 다시 만들 수 없다.
- 같은 이메일과 목적의 재발송은 60초 뒤부터 허용하고 1시간 동안 최대 5회 요청할 수 있다.
- 인증 실패 횟수는 최대 5회이며 인증번호 확인과 인증 완료 권한 소비는 같은 이메일과 목적의 가장 최근
  요청만 대상으로 한다.
- 새 인증번호 발송과 인증 완료 권한 소비는 같은 이메일·목적의 요청 잠금으로 직렬화한다.
- 새 인증번호 요청이 저장되면 세션의 이전 회원가입 인증 권한을 제거하며, 메일 발송이 실패해도 이전
  요청으로는 가입할 수 없다. 재발송 간격·횟수 제한처럼 새 요청이 저장되지 않은 실패는 기존 권한을 유지한다.
- 인증 완료 권한은 회원가입에서 한 번만 소비한다.
- 비밀번호는 8자 이상 100자 이하이며 영문, 숫자와 특수문자를 각각 포함한다.
- 이름과 닉네임은 각각 최대 50자, 생년월일은 과거 날짜, 전화번호는 국내 휴대전화 형식으로 받는다.
- 신규 회원은 `USER`, `ACTIVE`로 생성한다.

## 5. 소셜 계정

- 소셜 계정은 제공자와 제공자 회원 식별자 조합으로 식별한다.
- Google·카카오 로그인 링크는 공급자의 계정 선택 화면을 요청해 다른 계정으로 로그인할 수 있게 한다.
- 애플리케이션 로그아웃은 공급자의 로그인 세션을 종료하지 않는다.
- 소셜 이메일이 기존 일반 회원의 이메일과 같다는 이유만으로 계정을 자동 연결하지 않는다.
- 연결된 활성 `USER` 계정만 소셜 로그인에 성공한다.
- 연결되지 않은 신규 소셜 사용자는 이름, 닉네임, 전화번호와 생년월일을 입력한 뒤 회원가입한다.
- 소셜 전용 회원은 비밀번호를 `NULL`로 저장하고 회원과 소셜 계정을 같은 트랜잭션에서 생성한다.
- 기존 일반 회원과 소셜 계정을 연결하거나 연결을 해제하는 기능은 현재 회원가입·로그인 범위에 포함하지 않는다.

## 6. 계정 찾기와 비밀번호 재설정

- 이메일 찾기는 이름, 생년월일과 하이픈을 제거한 전화번호가 모두 일치하는 `ACTIVE` 회원만 조회한다.
- 조회 결과는 이메일을 마스킹해 보여 주고, 사용자가 선택한 이메일만 로그인 화면에 전달한다.
- 비밀번호 재설정은 `PASSWORD_RESET` 목적의 이메일 인증을 완료한 활성 비밀번호 계정만 허용한다.
- 새 비밀번호는 현재 비밀번호와 같을 수 없고 일반 회원가입과 같은 비밀번호 형식 규칙을 적용한다.
- 재설정 권한은 한 번만 소비하며 성공하면 해당 이메일의 기존 로그인 세션을 만료시킨다.
- 계정 존재 여부와 메일 발송 실패의 내부 원인은 비밀번호 찾기 응답에서 노출하지 않는다.

## 7. 프로필과 탈퇴

- 프로필에서는 이름, 닉네임과 전화번호를 수정한다.
- 로그인 이메일과 생년월일은 프로필 수정 대상이 아니다.
- 비밀번호 변경을 요청하면 현재 비밀번호, 새 비밀번호와 새 비밀번호 확인을 모두 검증한다.
- 비밀번호 변경을 요청하지 않으면 기존 비밀번호 해시를 변경하지 않는다.
- 일반 비밀번호 회원의 탈퇴는 현재 비밀번호와 탈퇴 확인을 요구한다.
- 비밀번호가 없는 소셜 전용 회원은 탈퇴 확인만 요구한다.
- 회원 탈퇴는 행을 삭제하지 않고 상태를 `WITHDRAWN`으로 변경하며 탈퇴 시각을 남긴다.

## 8. 관리자 회원 관리

- 관리자 목록은 일반 회원, 탈퇴 회원과 관리자 탭을 구분하고 최신 가입순으로 페이지 조회한다.
- 일반 회원 탭에서만 `ACTIVE`, `SUSPENDED` 상태 필터를 적용한다.
- 목록과 상세 화면의 이메일, 전화번호와 생년월일은 마스킹해 표시한다.
- 회원 상세에는 현재 상태와 정지 정보, 탈퇴 시각 및 상태 변경 이력을 제공한다.
- 정지된 회원에게는 정지 해제 동작만, 활성 일반 회원에게는 정지 동작만 제공한다.
- 화면에서 버튼을 숨기는 것과 별개로 `/admin/**` 접근은 Spring Security의 `ADMIN` 권한으로 강제한다.

## 9. 확정된 도메인 연계 결정사항

### 신규 회원 쿠폰

- 일반 회원가입과 소셜 회원가입은 회원 저장 후 쿠폰 도메인의 `CouponMemberCommandService`를 호출한다.
- 회원 생성과 신규 회원 쿠폰 발급은 같은 트랜잭션에서 함께 확정한다.

### 마이페이지 주문 요약

- `/mypage`는 인증된 `MemberDetails.memberId`를 기준으로 본인의 주문 현황을 보여 준다.
- 주문 현황은 `진행 중인 주문`과 `완료된 주문` 두 영역으로 구분한다.
- 각 영역은 `created_at DESC, id DESC` 기준의 최근 주문을 최대 5건까지 보여 주며 페이징하지 않는다.
- 진행 중인 주문에는 `PENDING_PAYMENT`, `UNDER_REVIEW`, `IN_PRODUCTION`, `READY_FOR_PICKUP`을 포함한다.
- 완료된 주문에는 최종 픽업이 끝난 `PICKED_UP`만 포함한다. 취소·반려·만료 주문은 두 영역 모두에서 제외한다.
- 일반 주문과 주문 제작 주문은 각각 `일반 상품`, `주문 제작` 배지로 구분한다.
- 마이페이지 메인의 주문 현황 영역은 최근 주문 요약만 제공하며 전체 주문은 주문 내역 화면에서 확인한다.
- 회원 도메인은 주문 테이블·Mapper·Entity를 직접 사용하지 않고 주문 도메인의 공개 계약인
  `OrderMemberQueryService`와 최소 응답 DTO를 사용한다.
- 주문 외 쿠폰·작성글·알림 요약을 마이페이지 메인에 추가할지와 추가 시 응답·페이징 책임은 아직
  결정하지 않았으며 [`team-plan.md`](../team-plan.md)의 미결정 항목으로 관리한다.
